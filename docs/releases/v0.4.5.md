# Remote Workbench v0.4.5

[中文说明](https://github.com/chanfeee/remote-workbench/blob/v0.4.5/docs/releases/v0.4.5.zh-CN.md)

Local Agent and MCP control, remote commands and files, readable local records.
This release brings the changes since v0.4.0 into a qualified stable package.

## Highlights

- Work in the selected existing remote directory, including non-Git build/run
  directories. Projects are not copied and no remote Codex CLI is required.
- Use shell text, literal argv, stdin and local-style patches. Combine selected
  reads, edits and checks while retaining complete local output and managed diffs.
- Share directories across chats. Managed edits coordinate per file; ordinary
  commands and background jobs no longer reserve an entire directory.
- View compact command/output and colored diff cards directly in chat. Each
  operation has an independent identity, so a later operation does not replace
  an earlier card. Collapsed content no longer leaves a tall empty frame.
- Keep the eight-tool session interface. Card previews use UI-only metadata;
  they do not duplicate their contents into model-visible tool text or add
  model calls. The normal command arguments and output remain conversation context.
- Keep the core runtime small: MCP/PyYAML are the direct default dependencies.
  Web/PTY and the SSH gateway are explicit `web` and `proxy` extras. Cost and
  historical test-evidence helpers are source-only offline tools.

Manual SSH authentication and existing OpenSSH ControlMaster connections remain
the normal path. New chats start local; remote failure does not fall back to
local execution. Original-job recovery, cancellation, timeouts, edit conflicts
and local audit/CLI access remain available.

## Validation

- Runtime qualification: 869 local tests passed with no skips; wheel/sdist and
  installed MCP startup checks passed. Python 3.10–3.13 CI covers the branch;
  the release workflow tests and builds the fixed tagged candidate again.
- The actual App loaded stable 0.4.5. After navigating to another chat and back,
  the user confirmed two command cards remained, then separately confirmed two
  diff cards remained and both line diffs could be expanded.
- Existing target/job origins and local history were retained. Private host
  details, fixtures, usage reports and installed-host fragments are excluded
  from the source and release assets.

## Install or update

Install on the local control machine. Download the wheel and
`runtime-requirements.txt` from this release, then run:

```sh
python -m pip install --constraint runtime-requirements.txt ./remote_workbench-0.4.5-py3-none-any.whl
```

For optional image/PDF/SVG previews, select the local wheel's `images` extra:

```sh
python -m pip install --constraint runtime-requirements.txt './remote_workbench-0.4.5-py3-none-any.whl[images]'
```

Configure an explicit host/directory and reuse your manually established SSH
connection. Reload the MCP after replacing an older installation. The App's
enable/disable selection remains under user control.

Assets: wheel, source archive, locked runtime constraints and `SHA256SUMS`.
The source archive also contains the offline benchmark helpers.

## Compatibility and scope

Saved records remain readable. Old chat cards lacking independent identities
are not rewritten. Full App restart and UI output-pagination controls were not
part of this acceptance, and near-local Agent latency/token parity is not claimed.
Coordination covers managed file edits, not arbitrary writes from external
terminals or inside opaque shell commands.
