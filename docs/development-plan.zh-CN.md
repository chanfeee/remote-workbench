# Remote Workbench 开发任务拆分

## 开发主线发布核验（2026-10-30）

本次将已完成的命令／读取／补丁往返优化、源码专用计时工具、目录占用恢复分开提交到 `main`。完整回归 809 项通过；安装中的独立 stable 锁热修通过 23 项专门测试。后者只包含锁生命周期修复，未带入性能候选；远端 `stable` 和版本 tag 不随本次源码 push 晋级。开发计时仍排除在发行包和正式入口之外，私有连接／用量／操作材料继续留在被忽略目录。CI 以实际发布提交的 GitHub 检查为准；本轮没有新增完整模型或真实 SSH 负载测试。

## 非 Git 工作目录修复（2026-10-27，本地待发布）

绑定只检查实际目录，不再探测 Git。普通目录的快照读取/编辑不要求 worktree 或 Git 程序，保留冲突检查、原子单文件写入、目标归属和逐次 diff。文本补丁可在普通目录使用已安装的 Git apply，不初始化仓库。Git 状态和 Git diff 仍是独立的显式能力。此修复不移动 v0.4.0，也不替换独立日常安装。


初始拆分日期：2026-10-25。初始核对基线：`develop` 提交 `bebcbea1427c39f46f6f2fcb579a33f72c6b2797`，版本 `0.3.0a11`。

**2026-10-26 范围更新**：当前 develop 阶段基线为提交 `ae380a9`（a13）。本轮只推进阶段1：MCP 记录明确目标上的命令、文件和后台生命周期事实；科研解释、验证是否充分及被操作项目的测试适用性由调用 Agent 和用户判断。`workspace_resume()` 默认只返回 binding/jobs/note 操作事实；显式读取旧测试历史时为只读，且不推断其当前适用性或触发 SSH 扫描。`workspace_snapshot()` 默认检查显式元数据与 Git 状态，只有显式启用有界内容扫描才计算指纹，不自动维护项目验证结论。Token/credits 计量仅用于手动运行的独立、可重复基准样本；Remote Workbench 自身的日常命令、编辑和测试路径不采集 token/credits 或模型费用，不因计量增加模型调用；日常工作流不在回复或 UI 中追加用量评估，也不以基准门槛阻止普通任务完成。此约定仅限 Remote Workbench 自身的执行与集成路径，不声明 Codex App 或模型服务如何记录账户用量。费用账本和脚本保留为测试辅助工具；完整操作记录与必要执行诊断照常保留。功能正确性、develop CI 与 stable 发布规则仍是各自的验收要求。

本文将用户建议拆成可验证的工作包。状态仅表示本轮核对结果；“已复现”不表示已修复。每个实现任务单独提交，按依赖集成，不把六个方向合成一个大重构。

## 可观察的原生命令接口（2026-10-28，本地候选）

当前交付目标是接近本地／直接SSH的用时、模型请求和用量，同时让用户独立查看实际命令、输入输出、执行位置和受管修改。不是通过让模型承担更多工作区协议、日志整理或验证计划来获得可见性。

候选在同一套八个工具中开放首次 `exec_command(host,cwd,command,stdin)` 的绑定／执行组合，以及主 `apply_patch(patch=...)` 的本地同款补丁与新增文件。默认命令预览恢复为16KiB，完整记录仍在本地；快照引用与标准补丁上下文保护同时保留，不要求先读取引用再计算行号。认证、重计算审核、目录协调、取消和原任务目标继续由执行层处理。固定三次调用模板不再是默认协议，也不等于模型请求数保证。

后续本地优化已缩短重复暴露的公共说明，并让同 host/规范化 cwd 的重复显式命令复用当前绑定。工具集合、原始输出和记录完整性保留；显式切换、连接校验与审核继续执行。完整回归 731 项通过，离线工具说明格式回放与同目录传输计数见 `VALIDATION.md`。后续新的本地／App 原生远程对照通过相同 21 项独立验收，仍未达到 2% 目标；原始数据保留在私有开发报告中。

延迟定位使用[源码工作区专用计时器](dev-timing.zh-CN.md)。它必须由开发启动器显式运行，不在正式运行模块中埋计时开关；开发工具及专用测试从 wheel/sdist 排除，不进入日常 MCP 回复、HTML 或 stable 安装。分层耗时与客户端外层等待分开报告，不据不完整边界推断 Python 为瓶颈。

2026-10-29 已据计时结果实现两项本地候选优化：仅为三个明确的只读工具补充 MCP 标注，并允许 `exec_command(read_files=..., edit_files=...)` 在确认成功后返回指定文件与编辑引用。两项均复用原有八工具接口、审计和编辑保护，未调整用户审批设置。完整回归 759 项通过，离线打包及实际 App 加载后的真实 SSH 小型验收通过；同任务检查与读取可少一次 MCP 往返。该验收为单次开发诊断，尚不等于完整 Agent 用时／token 达标；具体边界见 `VALIDATION.md`，原始测试资料继续保留在私有目录。独立 stable 未更新，临时工程配置已恢复。

后续核对覆盖完整测试问题：参数／补丁与调用脚本错误、目录和非Git行为、工具发现、重复上下文、输出回读、外层等待和审阅返工分别记录，不能用几个读取探针代替完整任务。公共说明进一步缩至656字符，shell约定保留在命令说明；成功前台回复只省去与实际cwd相同的启动路径及空身份字段。未知／失败／超时、清理限制和原始审计不缩减。生成调用桥的回归明确排除浏览器编码API依赖；任意外层JavaScript及模型内容错误仍不能由MCP保证消除。离线目录字节投影、模拟执行、实际App加载和完整模型对照继续分层报告。

进一步减少纠错调用：明确结束的非零检查也可返回调用者指定文件；`apply_patch` 可在检查／格式化后返回指定文件与新快照，默认不额外读取。相同失败检查→修复→格式化→观察要求的冻结前后本地worker回放，从4次MCP操作减为2次，底层模拟SSH传输仍为6次；原失败和成功输出、diff与最终内容一致。这证明了可合并的操作往返，不代表新的完整模型请求数、真实SSH耗时或token达标结果。认证／计算拒绝、未知、超时和冲突仍阻止后续读取，stable及审批设置未改。

HTML仅展示本地已有记录，不增加模型调用；受管补丁有逐文件diff，普通shell写入的覆盖范围保持明确。这里没有添加CLI代理、远端Agent、全目录扫描或新的运行模式。接口原型的回归结果与实际客户端性能是不同层次；没有把回放操作数当成完整Agent用量验收。

## 执行与模型往返优化（2026-10-27，本地待发布）

基线为实际最新 `main` 的 `fb34472`（0.4.1）。`read_file` 接受明确路径数组，已有绑定／检查／读取组合共用一次 SSH 文件读取，各文件保留独立快照、错误及记录，避免逐文件传输和重复模型往返。命令监督器直接启动原生 shell，并以完成通知唤醒，保留登录环境、进程组清理、取消和超时。首次绑定后先展示操作记录链接的要求不变。

本轮完成本地 worker 与模拟 SSH 的完整回归；局部测速仅用于识别执行开销，不能代替整个 Agent 的总耗时验收。没有付费模型复测、真实服务器执行或 App 加载验收，没有更新独立 stable 安装、分支远端或发布版本。结果见 `VALIDATION.md` 当前记录。

减少模型回合优先于继续微调单条命令时延：工具指引默认推荐已知文件任务使用“绑定／展示记录、检查／读取、修改／测试／审阅”三次操作，并复用新编辑引用。完整临时工程用例验证返回基线、修改、测试和审阅 diff 所需的材料；不追加一套 API、模型编排器或日常用量采集，也不把操作数量当作实测模型回合数。

## 决策与边界

- 本地保留 Agent 控制、聊天工作区、任务归属与审计；用户显式选择远端执行目标。普通本地任务仍使用原生本地工具，不自动进入远端。
- 聊天身份、仓库来源、实际工作目录分别建模。未来支持不同仓库、同仓独立目录和显式共享同一实际目录。
- direct 已有本地实现：只绑定实际目录，不再提供模式选择或旧副本兼容。新增目录协调限于同一本地状态、更新版本 MCP、同 SSH endpoint 已知重叠目录。详见模式契约；实际 App 加载需另验收。
- 保留人工认证、Agent 复用现有 ControlMaster 的流程。失去可用连接时明确失败，不自动重新认证。目录限制和 skill 都不等于操作系统沙箱。
- 保留完整功能、编辑保护、审阅、作业停止和恢复能力。MCP 记录可核验的操作事实；测试结论及其对项目是否适用由调用 Agent 和用户判断。统一的有界摘要保留，subTest 计数不确定时继续报告未知。
- Token/credits 计量限于手动运行的独立、可重复基准。Remote Workbench 自身的日常执行路径不采集用量或费用、不添加计量模型调用，也不在日常回复/UI追加用量评估；此约定不涵盖 Codex App 或模型服务的账户用量记录，也不阻塞普通任务完成。2% token 阈值与历史样本的口径和记录见[独立 Token 基准](token-budget.zh-CN.md)，不解释为费用百分比。
- 最初拆分完成本地最小复现；第一批现已由有文件边界的子 Agent 执行并经父级审阅、集成回归。远端目录默认值、全局安装入口和 stable 均未改变。
