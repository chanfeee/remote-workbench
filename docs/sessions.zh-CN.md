# Session记录与原目录执行

## 默认使用原目录

本地开发版的 `remote-workbench-session` 和固定入口 `remote-workbench-workspace` 都默认在用户指定的实际远端目录工作，不把目录当作模板，不自动复制工程。

Session MCP使用客户端明确提供的聊天身份分别保存绑定、审计、任务和恢复记录。固定工作区入口的 `session_id` 仍是每次MCP进程启动生成的UUID，不冒充聊天ID。记录独立不等于代码复制；多个会话可以显式共享同一代码目录。

固定入口的manifest中 `cwd` 就是工作目录；连接时只进行目录规范化和轻量元数据检查。运行状态位于远端用户状态目录下的独立session位置，不写进代码目录。没有Git的普通目录也可执行命令、读写文件；Git补丁和快照编辑自身的Git要求不变。

## 工作、代码、环境和结果位置分别指定

目录没有预设层级。代码、解释器、环境脚本和输出路径可同级、嵌套或在其他目录；由调用者明确指定，不通过复制工程建立关联。例如下面的虚构路径彼此独立：

```json
{"command":["/srv/env/bin/python","/srv/code/analysis.py","--output","/srv/results/result.json"],"cwd":"/srv/run"}
```

`cwd` 可为相对选定工作区的路径或绝对路径。需要激活脚本时，在同一命令中用该环境支持的方式加载；也可直接使用环境解释器/包装脚本。没有自动搜索环境、固定目录约定或跨调用保留激活状态。

记录保存实际命令、执行位置、输出和退出状态。后台任务固定启动时的目标、cwd和运行状态位置，后续切换目录不改变旧任务。

## 不再提供工程副本模式

执行入口只有实际目录。旧副本创建、交付与任务恢复接口已移除，不再接受 `directory_mode`。旧绑定无法继续执行，需用 `workspace_switch(host, 实际目录)` 重新选择。已有文件、提交、输出和本地历史不自动删除或迁移；旧副本中的活动任务需在原服务器终端人工接管。

绑定和显式 cwd 拒绝已知受管副本路径，也检查符号链接解析后的 cwd。该检查不是 shell 沙箱；不透明命令内部任意 `cd` 或文件写入仍由调用者和工程规范负责。

## 协调与操作记录

Session MCP使用同一data-dir时，共享受管目录协调。固定入口的direct会话在共享同一本地审计根时也协调重叠目录的文件修改、shell和后台任务；状态未知时不自动放行。两种独立状态后端之间不声称有统一分布式锁。

查询、日志和停止操作保持可用；文件哈希、补丁检查与原子写入仍独立生效。协调不约束外部终端、多控制端或命令超出声明范围的写入。

工具结果提供 **Remote Workbench 操作记录** 链接，无需专门调用信息接口获取链接。完整命令输出和受管diff保存在本地，HTML只读且可选；页面不可用或进程退出不会抹掉记录。查看器使用独立实例与系统分配端口，默认自动刷新。

每次命令使用账号默认登录shell，不限定zsh；`cd`和环境激活只影响当前调用。SSH不分配PTY，因此终端启动分支和作业控制可与交互终端不同。

这些行为是本地开发代码的契约，独立stable不随源码修改升级。使用新行为前应重载所有相关MCP实例，不能把旧进程当作已更新版本。
