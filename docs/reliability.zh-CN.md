# Develop：权限、任务、日志与受管编辑

这一轮保留本地 Agent、本地会话和操作记录、远端工程与测试、人工认证后复用 SSH ControlMaster 的架构。未增加远端 Codex CLI。日常 stable 使用经过单独验证的固定构建，不自动跟随 develop。验收使用本机模拟传输，不连接 IHEP/CERN；远端验收尚未进行。

## 已实现的工作流

长命令使用 `start_job(command=..., idempotency_key=..., wait_seconds=...)`。`timeout` 是远端任务的期限；`wait_seconds` 仅控制本次工具等待。等待到期返回原 `job_id`，不会停止任务。短命令的 `exec_command` 保持原有同步语义。

Session 模式在提交前持久保存重试键、命令指纹和原始工作区。相同键、相同参数不会再次提交；参数或目标不同则拒绝。提交后丢失响应时，先用 `resolve_operation(idempotency_key)` 恢复本地句柄，再查原任务。保留为 `reserved` 或 `unknown` 的提交不会被自动重启。明确在执行前拒绝的计算审核请求可在用户确认后用同一个键重新提交。未提供键的跨调用重试不保证去重。

`stop_job`、`job_status`、`job_wait` 以及本地操作记录读取不占用普通工程操作锁。控制任务始终路由至其创建时的目标，切换工作区不会改变它的归属。

后台任务返回前建立稳定的本地输出 ID。本地采集器使用独立、只读的 SSH 日志通道，将 stdout/stderr 增量追加到本地；模型无需反复查询来驱动采集。日志通道没有账号认证逻辑，master 消失后不能回退建立普通新连接。连接断开会显示同步断开和任务状态未知；断开采集器不会取消后台任务。重启后通过原作业的 `job_status`/`job_wait` 恢复采集，从本地已有字节继续；仅打开旧网页不会重启 MCP 或恢复已经停止的采集器。

`job_wait` 等待新字节、任务结束或等待期限，返回有限输出和后续字节游标。`search_output` 只搜索已经同步的本地日志，返回匹配位置、有限上下文和扫描游标；没有匹配且扫描未完成不能当作整份日志没有该内容。完整记录留给人查看，返回模型的片段受字节预算约束。

恢复边界：如果 MCP 已收到后台启动回包，只是 App 未收到回复，本地采集句柄已经存在，可以恢复。如果远端实际启动了作业，但成功回包尚未到达 MCP 就断线，幂等键仍可恢复原 `job_id` 并避免重复提交；随后 `job_status` 使用原有远端增量查询。后一种情况目前不会自动补建持久采集器，不能声称所有提交断线场景都已恢复自动采集。

## 基线与安全交付

本地开发版直接修改选定的实际目录，不创建工程副本，不提供副本交付流程。受管编辑使用文件内容哈希、预期状态或补丁上下文检查，并进行原子写入；外部修改会触发冲突。`git_diff` 只在明确调用时获取当前 Git 差异，普通 shell 中的任意写入不自动转换为逐文件补丁。

同一本地状态中的受管操作按已知重叠目录协调，后台任务在确认终态前保留占用。外部终端及多个控制端不在此保护范围内。旧副本和旧本地历史不删除，但旧副本绑定与任务不再兼容。详见[目录契约](workspace-mode-contract.zh-CN.md)。

## 恢复与测试证据

`workspace_note` 保存目标、约束、决定和下一步；`workspace_resume(include_legacy_test_history=False)` 默认只返回 binding、jobs 和 note 操作事实，不读取或修改测试缓存。显式设为 `true` 时只读返回 `legacy_test_history`，其对当前代码的适用性保持未知，且不触发 SSH 扫描。恢复摘要属于本地记录，不能证明远端当前状态；需要实际检查时再调用相应检查工具。

`workspace_snapshot(scan_content=False, max_files=10000, max_content_bytes=67108864)` 默认执行显式元数据与 Git 检查；只有 `scan_content=true` 才在文件数和内容字节上限内计算内容指纹。快照不与旧测试结果自动比较，也不自动维护被操作项目的验证结论。科研解释、验证是否充分和测试对当前项目是否适用由调用 Agent 与用户判断。

## 权限与记录边界

元数据核验必须只检查文件类型、所有者、权限、链接和是否能够打开，不读取凭证内容或计算凭证哈希。`0600` 不能隔离以同一用户身份运行、拥有相应本地文件访问能力的 Agent；放在项目之外也不等于禁止读取。Remote Workbench 无法替其他独立本地工具实施文件权限限制。实际凭证隔离仍需要调用端沙箱或操作系统权限边界。

ControlMaster 复用的是远端账号权限。私有工程目录是工作流隔离，不是远端账号的文件系统沙箱。主执行器、日志采集器及 SSH 网关统一禁止 master 丢失后的普通连接回退；人工建立 master 的入口保持可用。

MCP 命令入口对直接使用 `sshpass`/`SSHPASS` 的认证工作流作窄范围拒绝，相关参数不写入普通操作记录。这不是通用 Shell 安全解析器，不能识别所有脚本、嵌套解释器或秘密。密码、OTP 和登录交互应留在用户自己的终端，不应放进 MCP 参数、调试输出或普通操作日志。

本地操作记录目录默认 `0700`，新建记录和流文件默认 `0600`；这些权限仍不隔离同 UID 程序。命令、输入、输出和 diff 可能含敏感信息，目前没有通用脱敏保障，也没有自动过期删除。当前保留策略是人工管理、默认持续保留；应按自己的数据保留要求清理已结束记录，活动或状态未知的任务记录应保留用于恢复。认证记录不要混入开发审计。

“本地”描述的是控制程序、会话和审计存储的位置；使用云端模型时，进入模型上下文的代码和输出仍会发送给模型服务。

## 验收口径

本地测试覆盖重试去重、长操作期间取消/查询、不同目标的原任务路由、采集恢复不重复字节、不同节点状态未知、并行源修改拒绝交付、脏源工程基线、日志定位和历史测试标记。没有复现递归创建进程或资源耗尽。

效率比较使用总工具调用次数、请求/响应字节、重复读取字节和恢复调用次数。采集器内部搬运日志和 HTML 自动刷新不经过模型；字节数不是精确 token 账单。PTY 功能继续后置，没有为每条命令增加额外 LLM 审核。

一次可复核的本地合成日志比较：约 1 MiB 日志中在末尾放置一条已知错误，8192 字节逐页读取用了 128 次调用，返回 JSON 共 1,087,657 字节；按该错误字面量搜索（内部扫描预算 1 MiB）用了 1 次调用，返回 420 字节。两者均无远端连接，重复页面为零。这只说明“已知文字、单个末尾匹配”场景；不知道搜索词、错误分散或需完整上下文时，应另行测量总成本。

## 同一项目的本地与多服务器协作

`0.3.0a6` 的日常入口使用按 `threadId` 路由的 session 模式。新聊天默认 `mode=local`，不继承其他聊天的服务器；初始化、工具发现、`workspace_info` 和本地恢复摘要都不检查 SSH、不创建远端副本。MCP 可见、已有 SSH master、其他聊天选过远端，都不代表当前聊天需要远端。

本地命令继续使用 Codex 原生本地工具；选择一个远端目标只决定 Remote Workbench 工具的路径和服务器，不接管整个项目的命令。本地操作与几台服务器的操作可以在同一个项目、同一个聊天中交替进行。例如，可以要求“本地运行检查，在 cluster-a 的指定目录构建，再在 cluster-b 的指定目录测试”。Agent 按任务明确的地点选择工具，不为每条普通命令增加确认步骤。

- `workspace_switch(host, cwd)` 为当前聊天选择或恢复实际远端目录；另一聊天的目标保持不变。
- `workspace_use_local()` 仅清除当前聊天的活动远端绑定，保留历史与原目录任务。之后需要远端时可恢复原目标。
- 切换目标或切回本地以后，旧任务仍按创建时的服务器查询、等待和停止；不会被当前目标重新解释。
- 固定 workspace 入口继续保留，但 `workspace_info()` 默认仅读本地元数据；只有 `probe=true` 才显式检查连接和规范化实际目录。它不具备按聊天选择多个服务器的能力，不再作为全局日常入口。

这些规则限制自动路由，不构成“用户意图”的独立密码学证明；Agent 仍需按用户当前任务选择执行地点。文件系统与进程权限仍由所在系统控制。

日常版只在 develop 的固定提交通过测试和候选构建验收后手动推广，使用独立 wheel、venv、状态目录和版本记录。后续 develop 源码变动不会改变已安装日常版；保留旧 release 和启动器以便回退。现有 App 进程可能缓存旧 MCP 工具和说明，切换启动器后需重载 MCP，再验证新聊天的 `mode=local`。MCP 配置和重启行为见 [OpenAI 官方文档](https://learn.chatgpt.com/docs/extend/mcp?surface=cli)。
